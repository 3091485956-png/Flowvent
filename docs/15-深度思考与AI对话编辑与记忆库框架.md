## 一、AI 深度思考流(F1)

**替换假动画**:原四步进度是 `setInterval` 4500ms 定时推进(与 AI 实际进度无关),已删除。现在:
- `ai.generatePlanStream(form, {effort, onThinking, onDelta})`:请求 `stream:true` + `reasoning_effort`(默认 **high**,UI 三档可选;接口不认该参数时自动去参重试一次)
- SSE 逐 token 解析(`_sseParse` 纯函数,有单测):`reasoning_content` → 思考流面板实时上屏(深色终端风格、滚动、限长 6000 字);正文 token → "已撰写 N 字"
- **阶段由真实事件驱动**:请求发出=理解中 → 首个思考 token=规划中 → 首个正文 token=撰写中 → parse 完成=输出;秒表只报真实耗时,不伪造进度
- 容错:非流式网关(整包 JSON)自动回落;无思考字段的普通模型只显示撰写进度(诚实降级,不假装思考);30 秒无 token 判死(有 token 即续期),总上限 4 分钟
- E2E:SSE 桩(思考 36 字+正文 38 字)→ 面板可见、文本上屏、四步 done、effort=high 发出、方案落库
- 实现备注:E2E 首跑思考丢失,排查后确认是**测试桩手拼 JSON 畸形**(被 parseSSE 容错吞掉),产品代码无恙——桩改用 `JSON.stringify` 构造后全绿;顺带证明容错路径工作正常

## 二、AI 编辑对话(F2)

**入口收敛**:顶栏四个 AI 按钮(重新生成/润色·AI/精简/扩写·AI)→ **一个「AI 编辑」按钮**;章节标题右键收敛为「✦ 在 AI 编辑中处理此章节」;**选中文本右键 AI 保留**(点名);原四操作保留为面板内快捷 chips(重写/润色/扩写当前章节)。
- 右侧对话面板:消息流 + 快捷 chips + 输入框(Enter 发送/Shift+Enter 换行)
- **AI 直接改文档**:`ai.chatEdit` 严格 JSON 契约 `{reply, edit:{section,md}, save_pref}`;edit 经现有 `applySection` 应用(可撤销),章节标题容错匹配(精确/包含/中文序号);动作卡「已重写「xx」[撤销]」
- 上下文:活动信息 + 目录 + 聚焦章节现文 + 最近 6 轮对话 + 偏好摘要
- **对话进记忆**:每条用户指令 → `chat_message` 事件 → 并入 notesSeen 偏好检测管道(与特殊需求同闭环;含"以后/默认/记住/总是/每次都"强意图词直接达确认门槛);AI 判定的长期偏好(save_pref)→ 面板内「设为默认」按钮 → confirmed 级
- E2E:指令 → 章节真实更新(15:00→14:30)→ 动作卡撤销还原 → save_pref 确认入档 → chat_message 进管道,全通
