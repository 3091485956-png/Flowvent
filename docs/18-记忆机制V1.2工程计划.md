### 第一批:小成本·高价值(✅ 2026-10-19 完成,97 测试全绿)

- 本地精简(simplify)同样走对话框(无 AI 也一致)
- 测试:textOp prompt 断言;selection_op instruction 截断与 clause 检测断言

**F2 注入带保质期标注**(Claude B1)

### 第三批:体验升级(✅ 2026-10-19 完成,107 测试全绿)

> 实施记录(含用户追加三项):**Word 朴素化**——去表头/合计行填充与主题色,黑字黑线加粗合计,输出"正常文档的样子"(用户格式偏好自定义留 V1.2+);**去中心节点**——wiki 图与档案活视图均不再生成「记忆库」中心节点,无边视图自动网格布局;**F10 精灵**——SYS_BUTLER 契约 + butler() 关键词预选上下文 + applyActions(update 改名走 tombstone+互链重定向 / merge 并链 / delete 级联 / resolve;全程内存态单次落库,消灭中间保存竞态)+ 右侧对话面板(动作卡先卡后落,应用/忽略);**F11 笔记并入**——ep_memory 变更文件按 hash 增量合成 note_file_seen 事件进 AI 编译批次,noteHashes 随 norm 保留。E2E:精灵全链路(发送→动作卡→应用→改名+删除+tombstone+事件入档)通过。

**F10 记忆库精灵**(用户点 5)
- `ai.js` 新契约 `SYS_MEMORY_BUTLER`:输入=用户指令 + 页面清单(title+desc+level+cat,≤80) + 指令相关页全文(按 title/desc 关键词预选 ≤5);输出 JSON `{reply, actions:[{type:'update'|'delete'|'merge'|'resolve', key, key2?, body?, title?}]}`,铁律:只能改记忆,不能编造新事实;update 必须给 body 全文
- `wiki.js` 新增 `applyActions(actions)`:update→改 body/title(title 变更走 tombstone+新 key);delete→remove();merge→tombstone 次页并把其 links 并入主页;resolve→resolveReview;全部动作**先卡后落**:memoryview 对话里渲染动作卡,用户点"应用"执行(确认制,防误删)
- 对话事件 `memory_butler_op {action, key}` 入 rawLog
- UI:记忆面板右上"精灵"按钮 → 右侧滑出对话面板(复用 edit-chat 样式模式)
- 测试:契约构建/解析容错;applyActions 四类动作 + 确认制断言

**F11 笔记库并入编译源**(用户点 3b,原 V1.2 候选提前)
- `wiki.js compile()` 批次构造时,追加 `note_file_seen` 合成事件(来源 ep_memory files 清单:标题+hash+摘要 ≤200 字,只读不写)
- AI 编译可见笔记作背景;可产出 `kind:'note'` 引用页(body=摘要,sources 标 `note:<path>`);本地编译不产 note 页(确定性无摘要能力)
- 删除笔记文件 → 下次编译对应 note 页失去 source → 进 lint stale 建议删除
- 测试:桩 ep_memory → 编译批次含 note 事件断言
