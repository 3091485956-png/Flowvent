# 10 · 「无声助理」改造方案

> 状态:方案设计,未动代码 · 2026-09-30
> 新定位:**秒策,你的无声助理**——轻便、简洁、不麻烦、越用越懂。
> 一句话范式转变:**从「先问后做」到「先做后改」**。

---

## 一、定位推导出的四条设计原则

| 原则 | 含义 | 推翻的现状 |
| --- | --- | --- |
| **零输入启动** | 打开就能得到一版方案,靠智能默认而不是靠问;**不追问,直接给,错了你来改** | 一页 12 字段向导表单 |
| **屏幕轻盈,纸面庄重** | 公文感、仪式感只留给导出物;屏幕 UI 做减法 | 双线卡头/模块导航墙/按钮墙铺满屏 |
| **交互即学习** | 生成后用户的每一次修改都是"对话"——改什么=默认什么不合身 | 学习信号被动采集(docs/09 L2)从"增强"升为**地基** |
| **需要时才开口,一次一件** | 必要信息(如公司名)在用户撞见【待定】时就地要,一次只问一个 | 必填校验+红字+分组表单 |

与既有铁律的调和:新范式**更彻底地符合**"禁止 AI 追问"——原设计用表单问 12 个,新设计一个都不问,缺失信息用确定性默认+【待定】;一句话输入的解析是**关键词匹配**(类型/人数/日期),不是 AI 理解,零幻觉不破。

## 三、改造清单

### 1. 首页:从"仪表盘"到"一个输入框"

```
现在                                   改后
─────────────────────────            ─────────────────────────
大标题+长副标题                        秒策
[＋ 新建活动策划] 大按钮               (一句品牌语,≤10字)
8 张模板卡(带 tagline)                ┌──────────────────────────┐
"固定工作流·结构标准化·零幻觉"          │ 说说这次活动,回车即得方案   │
搜索 + 类型筛选                        │ 例:周六团建 60 人          │
历史方案列表                           └──────────────────────────┘
已归档方案折叠区                       [团建][生日会][年会][沙龙][发布会][培训][节日][户外]
                                      ──────────────────────────
                                      最近
                                      Q4 团建 · 昨天          >
                                      中秋游园会 · 9月25日     >
                                      查看全部 · ⋯设置
```

- **删**:Hero 长文案、工程标语、模板卡 tagline(点击后才知道也来得及)、归档折叠区(进"全部")
- **简**:8 模板卡 → 一行轻 chips(可点可忽略,不是必经之路);历史列表 → 最近 3 条
- **移**:搜索/筛选/归档 → "查看全部"次级页;AI 设置 → ⋯设置内
- **一句话输入的确定性解析**:匹配类型关键词(团建/生日/年会…)+ 人数(数字+人)+ 日期(周六/下周/X月X日);解析不出的字段全部用默认值,**绝不追问**。首版默认来自内置保守值,越用越被记忆接管(见 §4)

### 2. 向导之死:字段变成"结果属性条"

- 三步向导(表单→生成动画→编辑)整体移除
- 生成结果页顶部一行属性条,每个值**点击就地改**:

```
2026 秋季全员团建                    [导出 Markdown] [⋯]
10月24日 08:30 · 60人 · 户外 · 两天一夜 · 预算 ¥30,000   ← 逐项可点改
```

- 表单没有消失,而是**摊平成了结果的一部分**——用户看到具体值时改一个字段的成本,远低于空表单里凭空填 12 个
- 条件字段同样就地:点开"节日"属性 → 选端午/中秋;公司名缺省时文案处显示【待定】,用户点到【待定】即弹出单项小编辑(一次只要一个信息)

### 3. 编辑器:减掉 2/3 的视觉重量

- **按钮墙 → 2 常驻 + ⋯**:每模块只留「重写」「编辑」,润色/精简/扩写/复制/撤销收进 ⋯ 菜单(AI 未配置时 ⋯ 里只显示入口提示)
- **左侧导航 → 顶部迷你进度点**:10 个小圆点标识当前位置,点击跳转;侧栏信息卡删除(属性条已承载)
- **公文双线卡头只在导出物**:屏幕上改单线轻卡头;打印/导出维持公文排版+印章(卖点不动)
- **生成即达**:10 项逐个点亮动画改为顶部一行细进度条(≤2s)或直接呈现
- 保留:模块独立重写/一步撤销/自动保存(这些是"助理可靠感"的来源,不是负担)

### 4. 学习闭环:把 docs/09 从"增强"提为"地基"

记忆不再是可选增强,而是"敢用默认"的前提:

```
第 1 次:内置保守默认(一天/30人/公司内/员工)→ 用户改 7 处 → 7 个信号
第 3 次:默认已被信号修正(如总是改半天/户外)→ 用户只改 1 处
第 10 次:输入"团建"两个字,出来的就是"你们的团建"
```

- 信号源新增"生成后修改率"作为最高权重指标(改得越少=越懂)
- 偏好确认卡从"月度弹窗"改为**首页角落静默小卡**(可忽略,不弹窗打扰——"无声")
- 组织档案(价值观/称谓/禁忌)从建档表单改为**渐进收集**:撞见【待定】时收、导出前顺手收、用户主动进设置填
- 工作区概念弱化:单人默认无感,多公司用户在 ⋯设置里开启

### 5. 文案:全部换成助理语气

| 现在 | 改后 |
| --- | --- |
| "固定工作流 · 结构标准化 · 零幻觉生成" | (删除) |
| "十大标准模块一次成套:概述/时间表/…" | "一份完整方案,该有的都有" |
| "企业活动策划工作台" | "你的活动策划助理"(或仅"秒策") |
| "下一步:生成方案 →" | (随向导消失) |
| "带 * 为必填;未填写的可选项将以「待定」呈现,系统不会编造" | (随表单消失;【待定】本身就是提示) |
| "选模板、填一页表单,十秒拿出一套可提交的活动全案" | "说说这次活动,我来出方案" |

## 四、分期(每期独立可验收)

**P0 范式转换(核心)**:新首页(输入框+chips+最近3条)+ 一句话确定性解析 + 零输入默认生成 + 属性条就地编辑 + 向导移除。
验收:新用户从打开产品到看到完整方案 ≤3 次交互、≤15 秒;老方案数据无损打开。

**P1 减重**:编辑器按钮收敛(2+⋯)、侧栏改进度点、屏幕/纸面风格分离、生成即时呈现、文案助理化、设置收纳。
验收:编辑器首屏视觉元素数量下降 ≥60%(按钮/卡头/导航计数对比);打印产物与现版一致。

**P2 越用越懂**:信号采集接管默认值、修改率指标、首页静默确认卡、渐进档案收集、(承接 docs/09 P1/P2)。
验收:连续 3 次修正同一默认后,新方案默认值即修正值;"忘记一切"可全量清除。

## 五、明确不动 / 不做

- 10 模块结构、确定性引擎、模块独立重写、导出/打印公文排版——**卖点全部保留**
- 零后端/零上传/记忆本地——红线不变
- 不做开放式 AI 对话输入(一句话解析是确定性匹配;解析失败静默走默认,不反问)
- 不做推送/弹窗打扰(与"无声"相悖)

### 第三次修订:文档化编辑体验(2026-09-30 第四轮)

用户指令:编辑应为**直接文字编辑(WYSIWYG)而非 Markdown 源码**;策划案查看态是**一份完整文档**而非分块卡片;点「编辑」**新开标签页**进入编辑界面(查看态仅查看);参考 Ranuts Document 项目按本产品改造。

**Ranuts Document 调研结论**:它是 OnlyOffice WASM 引擎的浏览器 Office 编辑器(DOCX/XLSX),AGPL-3.0 + React 工程 + 巨型 WASM——直接集成有许可传染与架构破坏风险,且其场景是编辑 Office 文件。**采纳其产品理念**(独立编辑标签页/真实编辑而非预览/本地自动保存/编辑查看分离),以原生 contenteditable 在零构建架构内自研实现。

已落地:
