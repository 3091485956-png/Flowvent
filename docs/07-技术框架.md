# 07 · 技术框架

> Vibe_helper Stage 6 产出(技术视角)

## 一、最薄的一刀(Vertical Slice)

**用户选「公司团建」→ 填 12 项表单 → 3 秒内看到 10 个模块的完整方案 → 导出 Markdown。**
这条链路贯穿:模板内容包 → 生成引擎 → 存储方案 → 编辑器渲染 → 导出器。先让它全通,再铺开 8 模板与管理功能。

## 二、技术选型与理由

| 决策 | 选择 | 理由 | 被否方案 |
| --- | --- | --- | --- |
| 形态 | **纯前端静态应用,零构建** | 双击 file:// 即用、内网可托管、无供应链/构建链风险——企业办公最短路径;符合"轻量 MVP" | Vite+React(强)需构建与 Node 环境;Electron 桌面(强)分发重 |
| 框架 | **原生 JS(经典 script 标签,全局命名空间 `EP`)** | 无模块加载器依赖,file:// 下 ES Module 有 CORS 限制;文件按职责拆分,迭代空间等同工程化项目 | Vue/React CDN 引入(引入运行时却只用其 10% 能力) |
| 持久化 | localStorage(`ep_plans`/`ep_ai`/`ep_draft`) | 零后端承诺;方案为纯文本,体积远小于 5MB 限额 | IndexedDB(过度设计) |
| AI 层 | OpenAI 兼容 `POST {base}/chat/completions`,用户自配 baseURL/Key/Model | 智谱/通义/Ollama/私有网关全兼容;Key 仅存本地 | 硬编码任何厂商 |
| 内容生成 | **确定性模板引擎**:内容包(数据)+ 生成器(纯函数) | 结构 100% 可复现、参数驱动缩放、"重新生成"=换变体种子;这是产品第一卖点 | 纯 LLM 生成(与零幻觉矛盾) |

## 三、文件结构

```
app/
├── index.html            # 单页壳:home/wizard/editor 三视图 + 打印视图
├── .serve.js             # 临时静态服务器(本地测试用):node .serve.js 8137
└── assets/
    ├── styles.css        # 设计令牌 + 图标尺寸体系 + 三视图样式 + 打印样式
    └── js/
        ├── icons.js      # 内嵌图标资产:Lucide v1.49(ISC)+ IconPark v1.4.2(MIT),
        │                 #   离线零请求;由 tools/gen-icons.js 从 CDN 拉取生成
        ├── md.js         # 极简 Markdown 渲染器(标题/表格/列表/加粗/段落;⚠/✔ 渲染层转图标)
        ├── templates-a.js# 内容包 A:团建/生日会/年会/客户沙龙
        ├── templates-b.js# 内容包 B:发布会/培训/节日/户外
        ├── engine.js     # 10 个模块生成器(纯函数,form+pack→Markdown)
        ├── ai.js         # AI 增强层:配置/测试连接/润色/扩写(OpenAI 兼容)
        ├── storage.js    # 方案 CRUD/归档/复制/搜索 + 草稿 + AI 配置
        ├── exporter.js   # Markdown 导出下载 + 打印视图组装
        └── app.js        # 视图路由/向导/编辑器交互/toast(总装配)
tools/
└── gen-icons.js          # 图标资产生成器:node tools/gen-icons.js(重新拉取/换色)
```

**图标体系**:功能 UI 用 Lucide 线性图标(stroke 继承 currentColor,随文字变色);8 大模板标识用 IconPark 双色图标(注入 two-tone 主题色:描边 #0B2B66 / 填充 #1444C4,与品牌蓝一致)。全部 SVG 内嵌 `icons.js`(约 18KB),保持零外部请求与 file:// 可用;`EP.icon(name)` 供动态渲染,`<i data-icon>` + `EP.mountIcons()` 供静态标记。

## 四、关键数据结构

```js
// 内容包(每模板一份,共 8 份)
pack = {
  key:'team_building', name:'公司团建', icon:'🏕', tagline:'…',
  purposes:[…],                 // 推荐活动目的(≥3 条变体)
  schedule:{ half:[block…], day:[block…], dayAndHalf, twoDay },  // 时长档→时间表骨架
  segments:[{name,rule,props,duration,variants:[…]}…],           // 环节+变体
  staffing:[{role,duty,note}…],
  materials:{物料:[{item,unit,price,per}…], 道具:[…], 礼品:[…], 设备:[…]}, // per=按人数缩放
  budgetExtra:[…], copy:{poster:[…],moments:[…],notice:[…]},     // 占位符 {company}等
  script:{opening:[…],perSegment:[…],closing:[…]},
  risks:{common:[…],outdoor:[…],crowd:[…]},
  review:[…]                    // 复盘维度
}
// 方案
plan = { id, name, type, createdAt, updatedAt, status:'active'|'archived',
         form:{…12+条件字段}, modules:{ overview:{md,flags:{edited,ai},prev}, … } }
```

## 五、生成引擎约定(确定性保障)

- 全部生成器为**纯函数**,禁 Math.random 之外的隐式状态;变体选择用可重置的种子(`variantTick` 计数器)实现"重生成换内容、结构不变"
- 参数缩放规则:物料数量=人数×per(向上取整);预算=Σ单价×数量;时间表=开始时间顺序累加,按时长档选骨架并等比裁剪
- 未填参数:文案用「【待定】」占位,绝不编造具体地名/人名
- 模块输出统一为 **Markdown 字符串**(渲染、编辑、AI、导出四用同源)

## 六、AI 增强层协议

- 请求:`POST {baseURL}/chat/completions`,body 含 model、messages[system+user],temperature 0.3
- system prompt 按操作固定(润色=保持结构与表格不变仅改文风;扩写=只增细节不改结构),user=当前模块 Markdown
- 响应只取 `choices[0].message.content`;失败→抛错→UI toast+保留原文+可撤销

## 七、开发顺序(Stage 8 执行序)

1. index.html 骨架 + styles.css 设计令牌 → 首页(空状态)【即 Stage 7 静态原型,截图自查】
2. md.js + templates-a(团建先行)+ engine 十生成器 → 最薄一刀跑通
3. 向导三步 + storage 自动保存 → 新建→生成→编辑闭环
4. 编辑器全量操作(编辑/重生成/精简/复制/撤销)+ 方案管理 + 导出
5. templates-b 补齐 8 模板 + ai.js + 打印视图
6. 浏览器实测截图 → 修缺陷 → 交付验收(08)

## 八、原型决策说明(对 Vibe_helper Stage 7 的映射)

本产品为纯前端静态应用,**静态原型与最终产品同构**:先以真实代码搭出首页+向导+编辑器 UI(静态数据),截图自查后直接在原文件上接引擎与交互,不再产出独立原型文件夹。此决策已记录,避免同构产物的重复劳动。
