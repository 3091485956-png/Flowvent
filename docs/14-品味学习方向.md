# 14 · 「越用越有品位」优化方向(调研 + 方案 + 实现记录)

> 2026-10-01 · 背景:全真模拟体验报告(docs 见根目录《体验报告-秒策全真模拟.md》)实测「越用越懂你」4/10——
> 学会了统计事实(常场地/预算档),没学会策划品味(致辞限时/雨天备案/下午开场),停止提示即失忆(33 份方案对照为证)。
> **状态:T1 偏好确认闭环 + T2 品味归纳器 + 过往方案导入(intake)已实现(见文末实现记录);T3 择期。**

## 一、调研发现(2025-2026 业界与学界)

### 1. PRELUDE:从用户编辑推断"潜在偏好描述"(NeurIPS 2024,最关键发现)

[PRELUDE: Aligning LLM Agents by Learning Latent Preference from User Edits](https://neurips.cc) 证明了一条与我们架构完全兼容的路径:
- **不训练模型**。从"用户对 AI 输出的直接编辑"(编辑对)中,**推断一段自然语言的潜在偏好描述**,注入后续生成的 prompt
- 实验结论:用"偏好描述注入"指导生成,效果逼近用偏好对做训练(DPO 类),而成本是零训练、纯上下文
- **对秒策的意义**:我们的 `prev→md` 样本对(AI 原稿 vs 用户终稿)正是 PRELUDE 需要的编辑对,**基础设施已经存在**(E2 埋点 + flags.ai 限定),缺的只是"从样本对到偏好描述"的归纳器

### 2. "Ask, don't assume" 共识(2025-2026 交互范式)

[IaaT 框架(arXiv 2026.02)](https://arxiv.org)、[Severance Problem](https://www.emergentmind.com)、[Synthetic Strategy Memory(ACL 2025)](https://aclanthology.org) 一致结论:
- 信息缺失时**追问/确认,而非自信外推**;推断出的偏好必须**显式确认**后才成为高权重记忆
- UX 质量与任务准确率并列为个性化的一级指标——"问的方式"本身就是产品力
- **对秒策的意义**:体验报告 11.2-1 的批评("它不问,只猜——然后等我救")与学界结论完全一致;而报告 P0-2 期待的"要不要设为默认?"弹窗就是这一范式

### 3. ChatGPT Custom Instructions 2025 改版:偏好"特质化"

[OpenAI 2025-01-17 改版](https://help.openai.com/en/articles/8096356-chatgpt-custom-instructions):从纯自由文本转向**可选特质(trait)** + 文本并存;[官方文档](https://help.openai.com/en/articles/8096356-chatgpt-custom-instructions)强调"可随时修改移除"。社区共识:个性化来自 instructions + memory 注入,**从不做按用户微调权重**。
- **对秒策的意义**:偏好确认的 UI 应给"可勾选的选项"(致辞≤10分钟/必有茶歇/户外雨天备案),而不是让用户写句子;档案卡片天然就是这个形态

### 4. 编辑即偏好对的研究脉络(佐证,不采纳其训练路径)

[DITTO](https://www.scribd.com)(编辑增量构建偏好对做偏好优化)、[Dr Genré](https://arxiv.org)(2025,风格改写 RL)、PRELUDE 同族——它们最终都要训练;PRELUDE 的结论让我们**只取其"编辑对→偏好描述"的推断层,弃其训练层**,正合零后端约束。

## 二、方案:三层品味学习(由浅入深,每层独立可交付)

### 第 1 层 · 偏好确认闭环(把"重复"变成"默认")—— 先做

**机制**:检测「特殊需求」中重复出现的需求片段(规范化后精确/分句匹配,出现 ≥3 次且跨 ≥2 份方案),在下一次生成完成后轻提示一次:
> 检测到你常要求「致辞不超过 10 分钟」(已出现 12 次),设为默认偏好?

确认后写入档案新域 `facts.preferences[]`(文本偏好,带确认时间戳)——**显式偏好,注入优先级最高**,在记忆图谱呈现为可删除节点(复用 Preference 子图)。拒绝则计数清零,该片段冷却(不再追问)。

**为什么它是第一层**:零 AI 调用、确定性规则、完全可解释;直接命中体验报告最痛的一句("当我第 41 次写『致辞≤10分钟』,我期待它主动问我")。UI 特质化(确认弹层给选项)对齐 ChatGPT trait 范式。

**注入语义**:已确认偏好段 = 「该用户已确认的策划偏好(严格遵守;与本次活动信息冲突时以活动信息为准)」——与现有"仅供参考"的档案段**两级分开**(这是审查轮 B2 的设计)。

### 第 2 层 · 品味归纳器(PRELUDE 式离线归纳)—— 第 1 层跑稳后

**机制**:档案积累**新的编辑对样本**(AI 产出后首次人工修改的 prev/new,现有 E2 已限定此语义)至 K 对(如 8 对)时,在设置页/档案面板出现「归纳我的策划偏好」入口(或生成前静默判断)——调用**一次**用户自配的 AI 接口:输入脱敏的样本对摘录,输出 ≤100 字「策划偏好描述」(如"偏好短段落列表化、时间表精确到分钟、安全预案具体到责任角色")。结果进 `facts.preferences`(标注来源=归纳),档案卡片可查看/编辑/删除;归纳后样本计数清零,重新积累。

**为什么不是自动**:单次调用可控成本、用户触发可预期(无声助理≠无声扣费);归纳结果必须过"可审可删"这道闸——这正是 ChatGPT Memory 的 saved memories 形态。

**防污染**:归纳结果同样受"冲突以活动信息为准"约束;删除即失效;与第 1 层确认偏好并存时,确认级 > 归纳级。

### 第 3 层 · 终稿 few-shot(用"改过的成品"教风格)—— 择期

**机制**:用户编辑密度最高的方案(或被复制 ≥2 次的方案)视为"风格样板";生成时附 1 段(≤300 字)样板摘录作为 few-shot 示例:"该用户认可的成稿风格示例(仅供参考)"。

**依据**:风格传递最有效的方式是示例而非描述;样板 = 用户用编辑行为投票出来的,天然干净。**成本**:每案 prompt +300 字,需在质量与 token 间平衡——所以放第三层,待前两层效果验证后再评估。

## 三、明确不做(守卫)

| 不做 | 理由 |
| --- | --- |
| 按用户训练/微调(DPO 等) | 零后端不可能;PRELUDE 证明 prompt 层足够 |
| 不经确认的自动品味注入 | 违背 ask-don't-assume 共识;污染不可审计 |
| 全历史方案塞上下文 | token 成本与污染风险(ChatGPT reference history 的已知问题,docs/12 已论证) |
| AI 追问式创建(生成前问卷) | 体验报告 P0-1,但第 1 层落地后痛点大半消解;改变"一页表单 30 秒"定位,需单独决策 |

## 四、分期与验收口径

| 期 | 内容 | 验收 |
| --- | --- | --- |
| T1 | 偏好确认闭环(检测/确认 UI/两级注入/图谱节点) | 同一特殊需求写 3 次后出现确认提示;确认后新方案(零提示)包含该偏好;拒绝后不再追问;记忆图谱可见可删 |
| T2 | 品味归纳器(K 对触发/单次 AI 调用/可审可删) | 归纳描述 ≤100 字且入档案卡;删除后注入消失;归纳偏好不覆盖确认偏好 |
| T3 | 终稿 few-shot | 对照实验:有/无样板的生成在评审维度差异为正 |

**对应体验报告**:T1 直接回应 4.2(停止提示失忆)与 11.3-P0-2;T2 回应 4.4"策划决策无沉淀";T3 回应"文风"层面。报告核心数据结论"质量完全跟着输入走"在 T1+T2 后应可复测为"质量跟着输入+已确认品味走"。

## 实现记录(T1 + T2 + 过往方案导入,2026-10-01)

**改动面**:新增 `intake.js`(docx/PDF 文本提取);`profile.js` 新增 preferences 三源域(confirmed/intake/induced)+ notesSeen 子句计数 + pendingSuggestions + 两级 summarize + remove 扩展;`ai.js` 新增 parsePastPlan / inducePrefs(JSON 契约 + 容错);`memoryview.js` 导入过往方案/归纳偏好入口;`app.js` finishGen 确认弹窗;`memory.js` 图谱渲染 preferences(✓=确认级)。测试 runner 升级为 async 队列。

**T1 偏好确认闭环**:生成时「特殊需求」子句(6-40 字,规范化计数)跨方案重复 ≥3 → 下次生成完成后弹「设为默认偏好?」(modal 双按钮)→ 确认=confirmed 级(注入语「严格遵守」)/拒绝=冷却。**两级注入**:已确认偏好(严格遵守)→ 热区 → 必填字段事实 → 过往方案分析(排版与文风参考);摘要限长 200→280。E2E:3 次同需求→弹窗→确认→第 4 次**零提示**生成 prompt 含「严格遵守:致辞不超过10分钟」——体验报告 4.2 的"停止提示即失忆"场景闭环。

**T2 品味归纳器(PRELUDE 式)**:企业档案面板「归纳偏好」按钮——从方案库收集 ≤5 对「AI 初稿(prev) vs 用户终稿(md)」,≥3 对才可用;单次 AI 调用归纳稳定模式(至多 5 条,只归纳多份样本共有),入档 induced 级。E2E:3 对样本→归纳出「段落短,两句一换行」→入档→图谱可见。

**过往方案导入(intake)**:
- .docx:自实现 ZIP 目录解析——STORE 直读、DEFLATE 经浏览器原生 `DecompressionStream('deflate-raw')` 解压(**零依赖**,Chrome/Edge 80+),word/document.xml → 段落换行/标签剥除/实体还原
- .pdf:按需加载 pdfjs-dist@3.11.174(CDN 双源 + SRI 实算哈希,同 Cytoscape 模式)提取文本层;扫描件(无文本层)/离线给明确中文报错
- .md/.txt 直读;统一 `EP.intake.extractText(file)`
- 解析:文本(截 8000 字)→ `ai.parsePastPlan` → 严格 JSON {facts≤3, preferences≤8}(只提取明确体现、不推测)→ `past_plan_parsed` 事件入档(intake 级)
- **反哺排版风格**:intake/induced 偏好经 summarize 进入整案 prompt 的「过往方案分析(排版与文风参考)」段——用户导入自己写过的方案,AI 学它的排法
- E2E:真实 DEFLATE docx(含流程/预算段落)→ 提取 → 解析入档(腾讯×计数 + 2 条偏好)→ 第 5 次生成 prompt 两级共存且顺序正确

**测试**:52 → **58 通过 / 0 失败**(docx STORE roundtrip / DEFLATE 经 zlib 构造验证 / 三源事件 / notes 检测门槛与冷却 / 两级注入顺序 / remove preferences)。

**已知边界与择期**:确认子句与导入偏好可能近义重复出现在 prompt(如「致辞不超过10分钟」与「领导致辞不超过10分钟」)——择期做近义合并;PDF 提取依赖 CDN(离线可用 docx/md);归纳按钮的样本数 UI 提示文案已含门槛;T3 终稿 few-shot 择期。
