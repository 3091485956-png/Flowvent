# 11 · AI 整案生成重构(v2)

> 2026-09-30 · 用户指令:"推翻重做,文档编辑和 pdf 导出等都必须参考 Ranuts Document 项目,删除模板,直接 AI 生成整个 word 策划案,删除右键删除或者增加节点,整个编辑就是'Ranuts Document 项目+AI 功能'"

## 一、Ranuts Document 侦察结论(决策依据)

对 [ranuts/document](https://github.com/ranuts/document)(Vite+React+pnpm workspace 工程)做了完整树扫描(GitHub git/trees API,3243 文件全量):

| 组成 | 体积 | 说明 |
| --- | --- | --- |
| `public/fonts` + `ran-fonts` | ~184 MB | 内嵌字体库 |
| `public/web-apps` | ~131 MB | OnlyOffice 编辑器 UI(AGPL-3.0) |
| `public/sdkjs` | ~124 MB | OnlyOffice 编辑引擎本体(AGPL-3.0) |
| 其余源码/配置 | <2 MB | React 壳 + AI 层 |

**全仓库 444 MB,许可证 AGPL-3.0,依赖 Service Worker 与 HTTP 服务(file:// 不可用)。**

### 为什么不直接嫁接其代码

1. **体积与定位冲突**:秒策核心定位"轻便"(约 1MB 本体、双击即用);引入 444MB 引擎直接摧毁该根基,首次加载分钟级。
2. **AGPL-3.0 传染**:OnlyOffice 衍生代码要求整包开源并附带网络分发义务,与用户企业内部使用场景不匹配。
3. **构建链失效**:其形态依赖 Vite 构建 + pnpm workspace + Service Worker,与本项目"零构建、file:// 可用"承诺硬冲突。
4. **用户既有原则**:"参考集成 Ranuts Document 项目,但你需要根据我们的产品来修改这个参考的项目"、"借竞品气质不照搬交互"。

### 采用的口径

**产品形态与能力对标 Ranuts,引擎保持轻量自研等效实现:**

| Ranuts 的能力 | 秒策的等效实现 |
| --- | --- |
| 浏览器内编辑完整 Office 文档 | 整篇连续 WYSIWYG 文档(contenteditable,编辑往返经 htmlToMd) |
| AI 融入编辑 | 选区右键 AI(润色/扩写/重写)+ 章节右键 AI(重写/润色/扩写)+ AI 整案生成 |
| Office 文档导出 | 自研 word.js:CRC32 + STORE ZIP + 最小 OOXML → 真 .docx(零依赖) |
| 文档→PDF 保真 | pdf.js 克隆预览 DOM 块感知分页(与网页预览完全一致) |
| 自动保存 | localStorage 同步立即保存 + 失败显式告警(不谎报) |

## 二、变更清单

### 删除
- `templates-a.js` / `templates-b.js`(8 大内容包,约 1040 行)
- `engine.js`(确定性生成引擎,425 行)
- 首页"或从类型开始"模板 chips;表单"填入推荐目的"按钮;右键菜单的**删除此块/上方插入/下方插入/清空本节**(按用户指令移除增删节点)
- 编辑器工具条"打印 / PDF"按钮(与"导出 PDF"重复)

### 新增
- **`struct.js` 文档结构契约层**:9 类型枚举(含"其他"兜底)、`parseDoc`(AI 输出→章节,容错:剥代码围栏/前置寒暄/模型自带序号,### 及更深标题降级 ####)、`migrate`(旧 plan.modules 十大模块→plan.sections,读取时自动执行)、`simplify`(本地精简,离线可用)
- **`word.js` 真 .docx 导出**:自实现 CRC32 表、仅 STORE 的 ZIP 打包器(产物可复现)、最小 OOXML(Title/Heading1/Heading3 样式、等线正文、A4 sectPr、表格边框+表头/警示/合计/日期行着色、加粗 run、列表字面前缀、引用左边框);与网页预览同一份 Markdown 源,结构一致
- **`ai.js` 重写**:`generatePlan`(整案生成,超时 4 分钟,prompt 契约:## 章节式输出、四类必表格、预算对齐总额、未给信息写「待定」)、`regenSection`(章节重写,输出不含 ## 标题行)、`formBrief`(表单→活动信息摘要,所有 prompt 共用);选区 textOp 与润色/扩写保留
- 查看态与编辑页工具条「导出 Word」按钮

### 修改
- **创建流程**(`app.js`):校验通过 → 检查 AI 配置(未配→toast+直达设置)→ 四步进度动画与请求并行 → 解析 → 打开编辑器;**失败保留表单内容**(写回草稿,可重试)
- **数据模型**:`plan.modules{key:{md}}` → `plan.sections[{id,title,md,flags,prev}]`,章节数量与标题由 AI 决定;`storage.getPlans` 读取时自动迁移旧数据
- **右键菜单收敛**:章节标题菜单 = 重新生成本节/AI 润色/AI 扩写/本地精简;选区菜单 = AI 润色/扩写/重写 + 精简 + 复制;其余区域回落原生菜单
- 首页文案"AI 一键成案 · Word 式编辑 · 数据只存本机";设置页改为"AI 接口(生成方案必配)"并更新说明
- `md.js` **修复 splitRow 泄漏 bug**:原单次交替正则 `^\||\|…$` 非全局 replace 只剥行首竖线,`{:warn}` 泄漏为末列单元格(视觉模型在复查中抓到);改为三次独立替换,并加回归断言

### 测试基线
`test/run.js` 重写为 25 断言全绿:parseDoc 五项(切分/降级/标记保留/报错/id 稳定)、migrate 两项、类型表、md 渲染与转义、docx ZIP 结构(签名/EOCD/条目数/CRC 逐项校验)与 OOXML 内容(转义/着色/加粗/列表/引用/A4)、存储失败路径与多标签合并、toMarkdown、精简、AI prompt 契约。
另做 node 产物级验证:`unzip -t` 全部 OK + PowerShell XmlDocument 四部件良构校验。

### 浏览器实测(本地服务器 + 桩 fetch)
- 首页无残留 chips;创建面板 9 类型、无推荐目的按钮
- **AI 整案生成全流程**:桩返回带寒暄+代码围栏+### 的"脏"输出 → 3 章节正确解析、序号剥离、深层标题降级、加粗/{:warn} 保留
- 旧版 modules 方案打开自动迁移(空模块剔除、flags 保留);我的活动 chips 按库中实际类型生成
- 编辑页三类右键菜单符合预期(无增删节点项);Word 导出构建 9535 字节 PK 产物、toast 正常
- 视觉模型评审三页:首页✅ / 编辑器复查✅(发现并修复 {:warn} 泄漏)/ 创建面板✅;抽屉高亮对比度程序化核实 7.91:1(AAA,模型误报)

## 三、产品语义变化(需知悉)

1. **AI 从可选变为生成前提**:不再有离线生成;未配置 AI 时"AI 生成方案"引导至设置。已有方案的查看/编辑/导出仍完全离线。
2. **"零幻觉/结构固定"卖点随之终结**:结构与内容由 LLM 决定,靠 prompt 契约 + parseDoc 容错约束;质量上限取决于所配模型。
3. .docx 列表为字面项目符号(非 Word 原生编号);如需可后续补 numbering.xml。
